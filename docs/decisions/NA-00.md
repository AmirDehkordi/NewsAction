# NA-00 decisions — scaffold, time / lock / ledger primitives, PREREG v0

Date: 2026-10-24. Branch: `feat/NA-00-scaffold`. Self-audit: `artifacts/NA-00/REPORT.md`.

## Decisions

### Calendar
- **`exchange-calendars==4.13.2`, pinned.** It already treats 2025-01-09 (National Day of Mourning)
  as closed and has the six 2024–2025 half days. `calendar.FORCED_CLOSURES = (2025-01-09,)` is
  applied anyway, so a future release cannot silently reopen that day (it is a no-op on 4.13.2).
- 4.13.2 calls `Series.values` on tz-aware data, which pandas 3.1 deprecates. That one warning is
  suppressed only around `get_calendar`. The test suite turns every other warning into an error.
- The session table covers 2010-01-01 … 2027-12-31 (`configs/project.yaml` `calendar`). Dates
  outside it raise `CalendarError` instead of guessing.
- **Windows are (start, end].** An instant equal to close(prev) belongs to W2(prev), not to W0(s).
  `session_of_w0(ts)` is `None` for instants in (09:15 ET, close] of a session. `window_w0` and
  `session_of_w0` take an optional `cutoff` for the PREREG §11.6 robustness runs (08:00 / 09:30).
- Added `session_minutes(d)` (390 / 210) for the half-day σ_id scaling NA-01 needs (PREREG §5.4).

### Availability registry (`pit`)
- **Kinds are `static, t_minus_1, w0, d1, w2, d2_reaction, post`.** PRD S7 lists six kinds, but
  its D2 rule also admits `"d2_reaction"`, so it is a seventh kind. Visibility is cumulative:
  D0 = {static, t_minus_1, w0}; D1 = D0 + {d1}; D2 = D1 + {w2, d2_reaction}. `post` is never visible.
- **Targets are `post` by name.** `z_id` is `post` (AC4) although z_id,t is known after the
  close. A D2 input that needs a same-day quantity must use its own `d2_reaction` column
  (e.g. `g_d2`), so a label column can never become a feature by accident.
- Duplicate keys in any config YAML raise `ConfigError` (PyYAML would silently keep the last one).

### Lock
- **Two flags in `configs/frozen.yaml`.** `frozen_requested` is set by NA-11; `lock.freeze()`
  refuses without it. `frozen` is flipped to `true` by `lock.freeze()` itself, just before hashing,
  so the hashed file says it is frozen. `is_frozen()` is true iff a well-formed
  `artifacts/NA-11/freeze.json` exists. The record is created exclusively, so a freeze can never be
  overwritten.
- **PREREG hash and the Deviations log.** See PREREG §15, row 1: the hash covers PREREG up to the
  §15 heading, and §15 is checked append-only by prefix sha256 and byte length.
- **Read and write routes.** `lock.read_sealed(name, purpose)` is the read path: logged, and the
  sha256 is verified against the manifest. `io.read_parquet` refuses the sealed directory.
  `lock.write_sealed(df, name, …)` lets later chunks (e.g. NA-10 bars) write 2026 data without ever
  naming the sealed path. It is logged with purpose `"write"`.
- Access-ledger entries carry {ts, caller (`file:function:line` of the first frame outside
  lock.py), name, purpose, allowed, reason, git_sha, prev}.

### Blinding scan (`tests/test_blinding.py`)
- PRD S4 requires `paths.SEALED`, so `paths.py` may *define* the location. It is still scanned for
  dates and may import only stdlib modules. Calls to the lock API (`lock.sealed_path`,
  `lock.read_sealed`) are the sanctioned route and are allowed everywhere.
- Flagged in `src/` outside `lock.py`:
  - test-period date strings (`2026-0[1-9]|2026-1[0-2]`, `2026MMDD`, `2026/MM`);
  - `date(2026, …)`-style constructors;
  - non-docstring strings containing "sealed";
  - the identifiers `SEALED` / `.sealed`;
  - any use of `io._read_verified` outside io.py.

  A self-test plants each pattern and checks that it is caught.

### Ledgers
- **Hash-chained JSONL.** Each line has `prev` = sha256 of the previous line, so edits, deletions
  and reorders are detected (`make ledgers`). Writes happen under `filelock` and are fsynced.
- **Reservations are written to the spend ledger**, so concurrent processes see each other's holds.
  A final `record` or a `release` closes a reservation, and a batch reservation can be spent
  incrementally (`final=False`). `record()` always writes the line, since money already spent must
  be recorded. It then raises if the spend had no reservation (and cost > 0) or if a cap is now
  exceeded.
- Chunks not listed in `budget.chunk_caps` have a $0 cap. The $1.8 reserve is recorded
  (`reserve_usd`) but allotted to no chunk; using it is an operator decision.

### I/O
- `write_parquet` requires a default RangeIndex and unique string columns. Writes are atomic
  (temporary file + rename) and deterministic: rerunning the converter reproduced all five sha256
  values.
- A `Data/` input is fully hashed on its first read. Later reads compare size + mtime, and a change
  raises `InputChanged`. `make manifest-deep` re-hashes all inputs.
- `make manifest` also fails on unregistered parquet files under `work/` and on any
  DATA_CONTRACT sha256 that differs from the manifest (GAC5 automated).

### Pickle conversion
- Rows are kept verbatim: NaN values, the 43 duplicate earnings stamps and the source order.
  `None` entries (106 earnings tickers, 7 share tickers) contribute no rows. CPI `value` NaT
  becomes NaN.
- `earnings_ts` stays naive. The source records no timezone, and America/New_York is only a guess.
- `market_prices.parquet` is a byte-for-byte copy (sha256 equals the input's). Like `Data/`, it
  contains 2026 rows; see PREREG §15, row 2.
