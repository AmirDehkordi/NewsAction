## Pipeline

- **One stage per process.** `python -m newsaction.train.build --stage labels | export | notebook | kernels |
  plan | import | cards`. Configuration: `configs/training.yaml` (every constant with its PREREG / PRD source;
  `tests/test_train_config.py`).
- **Local stages** (labels, export, notebook, kernels) are done. The Kaggle stages (pilot → plan; runs →
  import → cards) wait for the runs.
- **Peak RSS:** labels 0.3 GB, export 6.3 GB (the three state files and the examples in memory), the real-
  weights notebook smoke run on MPS 3.4 GB, `make verify` 8.2 GB.
- **Determinism.** labels and export were each run twice: all 8 files byte-identical. `dataset_info.json`
  records only its inputs' sha256 (states, labels, `training.yaml`, `questions_v1.yaml`), not the git sha
  or the hash of every config, so the dataset does not change with a commit or an unrelated config edit.

## Labels (S1)

- **Bins** are closed on the left, as the codebook's move words (PREREG §6.11): [0, 0.5) negligible,
  [0.5, 1) small, [1, 2) moderate, [2, 3) large, [3, ∞) very large. H-react = 4 + sign(e5)·bin(|e5|) gives
  Q1's nine levels; H-mag = bin(|z_cc,t|). Q1's option texts ("> 3 typical daily moves", "(2–3)") are
  approximate at the edges; the codebook is the operative rule.
- **H-cont:** x = sign(G)·y2 with G = z_cc,t (`g_d2`) and y2 = z(O_{t+1}→C_{t+5}); reverse if x ≤ −0.5,
  continue if x ≥ 0.5, stall otherwise (|x| < 0.5, like "negligible"); only |G| ≥ 0.5. Index order = Q6's
  options (reverse, stall, continue), asserted.
- **Purge:** the panel's e5 and y2 are already NaN past the split end (NA-01 target code); `check_purge`
  asserts every label's horizon ends in its split. Train: last react label 2025-06-24 (horizon 06-30), last
  cont label 2025-06-23, mag through 2025-06-30.
- **One row per event key** (company, session): D0 and D2 events of the same session share e5, z_cc and the
  cont label (every D0 key is also a D2 key). Val-B rows exist for NA-11; NA-08 computes no statistic on them.

## Dataset (S2)

- **Contents.** Train 174,320 examples (labelled only), val-A 62,404 (every state; `label_index` null where
  purged or missing; `embargo`), val-B 43,382 and test 65,204 (Call A D0 and D2 only) with exactly
  `EVAL_COLUMNS`: no label column, no outcome. Files 70 / 28 / 17 / 23 MB (snappy parquet).
- **Questions by source.** Call A D0 and D2: react + mag; Call B: react + cont. H-mag is asked of Call A D2 too:
  it is the ex-post magnitude of the day's news (A3.1's D2 Call A reading), and the label is defined there.
- **Data minimisation.** The dataset holds the PRD's columns only. `event_id` ("W0:{company}:{session}") is
  kept as the PRD lists it; the model never reads it.
- **Option order.** `question_json` is serialised without sorting keys, so Q6's options stay in the battery's
  order (reverse, stall, continue); canonical (sorted) JSON would reorder them.
- **Block dropout (PREREG §9.1)** is a copy per drawn state, as the PRD specifies for the reaction block:
  u = sha256("2026:{block}:{source}:{event_id}") / 2^256.
  - `no_reaction`: Call B train states with u < 0.3 get a copy without `reaction_so_far`, asked react only
    (cont needs the reaction). 8,680 copies.
  - `no_context`: any train state with u < 0.1 gets a copy without attention, company and market (the
    "context block": every block but news and the reaction), asked the source's questions. 15,105 examples.
  - **Finding:** every Call B state without its reaction block is byte-identical to the event's Call A D2
    state (NA-04 builds both from the same news and budget; 48,197 of 48,197). So the `no_reaction` copies
    duplicate Call A D2 react examples: they add weight, not a new input. Likewise 9,481 Call A D2 train
    examples equal their Call A D0 twin (state and label). 18,344 of the 174,320 train examples (10.5%) are
    exact duplicates. **Operator decision (2026-10-26): keep them as specified**; the notebook's
    `TRAIN_VARIANTS` can still drop the copies without a new upload if the quota plan needs it.
- **Tokenizer.** Laya's typed-decisions tokenizer and ModernBERT-large's (45bb4654, NA-03 / NA-04) give
  identical ids on 4,500 sampled states, and NA-04's `n_tokens_state` equals Laya's count on all of them.
  The notebook re-checks every state's count on Kaggle.

## Head length and MAX_LEN (operator decision on NA-04 owner decision 2)

- **Head length** = 143: the longest trained question in Laya's rendering (react, Q1: "score question: …" and
  nine "[MASK] level k: …" options). mag 77, cont 64. With 3 special tokens the head is 146. The export and
  the notebook refuse a head length that cuts a question.
- **Conflict found.** NA-04's budget measured Q1 as canonical JSON (132 tokens), which lets a Call A D0 state
  reach 889 tokens. In Laya's rendering react leaves 1,024 − 146 − 1 = 877 tokens for the state. Five D0
  states (4 train, 1 val-A; 0 val-B, 0 test) are longer, by 4–12 tokens (`dataset_info.json` `truncation`).
  At MAX_LEN 1,024 their last article's tail and the closing brackets would be cut on the react question.
  The operator's two rules ("no state may be cut", "MAX_LEN stays 1,024") cannot both hold for these five.
- **Operator decision (2026-10-26): MAX_LEN 1,036**, so no state is cut (PREREG §15 NA-08 row). The other
  options were to keep 1,024 and cut the five, or to tighten NA-04's D0 budget by 12 tokens (a D0 rebuild that
  would change state hashes NA-05 / NA-06 already use). Only `dataset_info.json` (the sequence check) changed;
  the parquet files did not.

## Notebook (S3)

- **Structure** (adapted from Laya's official 2×T4 notebook): parameters; environment and GPU check; pinned
  install (`laya==0.4.14`, `transformers==5.20.2`, the local versions); dataset check (every file's sha256 vs
  the dataset's manifest; no label column in val-B / test); model download at the pinned revision with the
  weights' sha256 checked; `%%writefile train_ddp.py`; `torchrun` launch; summary. No benchmark and no Hub
  push cells. The program lives in `src/newsaction/train/notebook/train_ddp.py` (ruff-linted, excluded from
  `mypy --strict`, exported, not imported); `nbbuild` embeds it and the committed notebook must equal the
  build (`tests/test_train_notebook.py`).
- **Pins.** Laya: `convaiinnovations/laya` @ `55cf4c4e…` (laya 0.4.14's reviewed pin; its typed-decisions
  files equal HEAD `7b928d82…`, same blob ids), weights sha256 `4fa56de7…` (= the LFS oid and the local
  cache). Anchor: `answerdotai/ModernBERT-large` @ `45bb4654…` (NA-03's tokenizer revision), weights
  `44510fec…`.
- **Anchor head.** Laya's `DecisionModel` (2 transformer layers, option-marker scorer, act head) built by
  `laya.common.build_model` around the Hub encoder, freshly initialised under `torch.manual_seed(SEED)`; the
  head configuration (2 layers, act costs) is fixed in the parameters, so the anchor downloads nothing from
  Laya. Laya-Fin loads all of Laya's weights (`strict=True`).
- **Act head frozen.** It is unused (Laya's model card: no usable signal) and gets no gradient from the loss;
  freezing it lets DDP run without `find_unused_parameters` and changes nothing else (AdamW skips parameters
  without gradients).
- **Loss.** `laya.train.rlcd_loss` (the official objective: proper-scoring policy gradient + soft cross-
  entropy; RPS for the two score heads). Early stopping uses the deterministic val-A cross-entropy, pooled over
  heads, patience 0, ≤ 3 epochs.
- **Schedule.** Linear warm-up over 3% of the updates, then cosine to 1e-6 (the official notebook has no
  warm-up; the anchor's head starts from random weights). Same for both inits.
- **Batching.** Length-bucketed random micro-batches (sort within chunks of 64 batches, shuffle the batches),
  sharded equally across ranks; `no_sync` during accumulation; effective batch 8 × 2 × 4 = 64.
- **Determinism.** Per-rank torch seeds, `torch.use_deterministic_algorithms(True, warn_only=True)`,
  `CUBLAS_WORKSPACE_CONFIG`; the repro control measures what remains.
- **Time budget.** Training stops before 11.25 h (the 12-hour session limit minus setup and the final
  inference), so a run always writes outputs from its best epoch.
- **Weights behind the predictions.** The best epoch's fp32 state is kept in memory and restored before
  val-B / test inference, and the checkpoint is saved in fp32, so NA-11's test Call B inference uses exactly
  the weights of the val-A / val-B predictions (Laya's own `save_checkpoint` halves them). Laya's vendor
  temperatures are neutralised in the saved config; the val-A ones are in `na08_temperatures`.
- **Val-A only.** Early stopping, the temperatures and every metric use val-A rows with a label outside the
  first 5 sessions (PREREG §4.2; the embargo is a rule for evaluation, applied here to fitting too). The PRD's
  "ECE before/after on val-A and val-B" (S3) conflicts with AC5 and the val-B gate (CLAUDE.md C13), and the
  dataset holds no val-B label: NA-08 reports val-A only, NA-11 the rest.
- **Temperatures.** One per (question type, option count) = per head (react score:9, mag score:5, cont
  choice:3); argmin NLL over [0.05, 20], log-grid then golden section; no clamp (Laya clamps to [0.5, 5]).
- **Pilot.** One kernel, three `torchrun` launches: Laya with gradient checkpointing (micro-batch 8), Laya
  without it (micro-batch 4 × accumulation 8, same effective batch; optional: an out-of-memory failure is
  recorded) and the anchor. 5% of train, 200 micro-batches per GPU, then a rehearsal of the whole output path
  on 2,000 / 500 / 500 val-A / val-B / test rows. The PRD makes checkpointing "if needed"; off would save
  ~25% of compute if the memory allows.

## Pilot and the run plan (S4)

- **Measured** (2×T4, the pilot's three launches; `artifacts/NA-08/throughput.json`):
  - training 8.24 seq/s (Laya) and 8.21 (anchor), micro-batch 8, gradient checkpointing on;
  - inference 31.9 seq/s;
  - peak 10.5 GB of the T4s' 14.6 GiB.
- **Checkpointing stays on.** Off, micro-batch 4 passes the memory probe (10.1 GB) but runs out of memory once
  AdamW's states exist.
- **One epoch per run.** An epoch is 5.9 h, so a 1-epoch run is ~7.4 h and 2 epochs (13.8 h) do not fit the
  11.25 h budget. Splitting a run over sessions (resuming from a checkpoint) would double the quota.
  Every run therefore trains 1 epoch, within PREREG §9.1's ≤ 3; the cosine schedule spans that epoch.
  Laya's own typed-decisions fine-tune also ran 1 epoch (its config: `epochs_completed: 1`).
- **The controls predict val-A only** (PRD S5 needs no more): a split not predicted is read with a 0-row
  limit (`PREDICT_SPLITS`, notebook glue only, so `train_ddp.py`, and with it the pilot's verification,
  is unchanged). This saves 0.94 h per control.
- **Operator decision (2026-10-26): the full plan, hedged.** Week 1: shuffle-s13 and laya-s13/17/23. Week 2:
  anchor-s13, repro-s13, anchor-s17, anchor-s23. Total 58.3 GPU-hours. The repro run comes before the last two
  anchor seeds, so a short quota degrades to the PRD's reduction (anchor seeds → 1) and keeps the control.

- **Operator decision (2026-10-27): one seed per model, within this week's quota** (PREREG §15 NA-08 row 2).
  - **Runs:** laya-s13 (running), then anchor-s13 and repro-s13. laya-s17, laya-s23, anchor-s17 and anchor-s23
    are deferred (`deferred: true` in `configs/training.yaml`), and each model's reported "ensemble" is its

  - **Seeds can join later unchanged.** `import_preds.ensemble_runs` takes every planned seed run that has been

## Import, cards, controls (S5, S7, S8)

- **Raw downloads** are Arrow IPC (`na08_*`), so `make manifest` does not take them for unregistered parquet;
  each is checked against the notebook's sha256 before use and recorded in the registered run file.
- **Verification** (`import_preds.verify_run`): this planned run (name, init, seed, shuffle flag); pinned
  revision and weights sha256; program sha256 = the committed `train_ddp.py`; the dataset files' sha256 = the
  local manifest (AC1); val-A-only fitting; no label read from val-B / test; `hub_push: false`; head and
  sequence lengths; cut states ⊆ the export's; each prediction file's exact example ids, option counts, sums
  and softmax(logits / T).
- **Ensemble** = the mean of the seeds' val-A-calibrated probabilities (PREREG §9.1); it has no temperature of
  its own. The controls are not part of an ensemble.
- **Common prediction schema** (long; one row per event, call, question): defined here for the trained models
  (NA-09 writes the baselines' later). Derived: N̂ and E|N̂| (PREREG §7 midpoints); H-mag E[level] with
  midpoints (0.25, 0.75, 1.5, 2.5, 3.5) and P(|z| ≥ 1); H-cont C = P(continue) − P(reverse), J analogue = C
  (continuation = under-reaction), W analogue = P(reverse).
- **Card ICs** (val-A, embargo out, ≥ 10 events a day): D0 N̂ vs z_cc,t (PREREG §8.5's metric) and vs e5; D2
  Call A and Call B N̂ vs e5; H-mag vs |z_cc,t|; C vs sign(G)·y2. Controls: shuffled-label |t| < 2 on D0 N̂ vs
  e5 (PRD S5); reproducibility |Δ IC| ≤ 0.003 on D0 N̂ vs z_cc,t **and** vs e5.
- **Trials** (CLAUDE.md B10): each run and each ensemble on its primary metric, kind `trained_model`, split
  val-A, appended once (identical records are not repeated).
