## Package layout (`src/newsaction/dm/`)

- `__init__`: configuration (`configs/dm.yaml` → `DmConfig`), paths of the NA-05 artifacts, `DMError`, `Refused`
  (with the rule that refused), `CacheMiss`.
- `schemas`: request and response models and the strict parser.
- `cache`: the sqlite cache and its key.
- `costmodel`: catalog prices, billed bytes, projections, the pilot calibration.
- `client`: refusals, cache, budget, transport (the only module that opens a network connection to a decision
  model).
- `catalog`: snapshot and eligibility; writes `eligible_models` into `configs/frozen.yaml`.
- `laya_local`: the local checkpoints.
- `parse`: PREREG §7 / A2.4 derived quantities.
- `canary`: canary_v1, synthetic states, baseline and drift comparison.
- `runner`: registered state files → `CallSpec`s → tidy answer frames (for NA-06 onwards).
- `pilot`: the NA-05 measurement pilot, one stage per process.

`io.register_artifact` (new) registers a committed file under `artifacts/` in `work/MANIFEST.json`, so `make
manifest` re-hashes it and checks its DATA_CONTRACT entry like a `work/` file. NA-05 uses it for its five committed
artifacts (the canary baseline is a parquet a later chunk reads).

## Requests and responses (S1)

- **Provider.** `DecisionRequest.provider` is a model whose only field is `data_collection: Literal["deny"]`,
  with `extra="forbid"`: no code path can build a request that allows data collection or sets other routing.
  `params` (extra body fields, e.g. the pilot's `seed`) may not override `model`, `state`, `questions`,
  `provider` or `session_id`.
- **Question types.** `choice` (≥ 2 options) and `score` (2–10 levels); `noul` is refused (PREREG §7).
- **State.** An object is sent and hashed as its canonical JSON (sorted keys, compact, UTF-8), which is exactly
  NA-04's `state_json`, so `request.state_sha256()` equals the state file's `state_sha256` (checked by
  `runner.state_specs`). The order of questions and of a choice's options is kept as written.
- **Strict parse.** Problems (the answer is invalid; its probabilities are not used): missing `type`; a type other
  than the one asked; a missing typed field; a choice that is not an option; missing probabilities; probability
  keys that are not exactly the options (a score's "0" … "k−1"); a probability outside [0, 1]; a sum off 1 by
  more than 1e-6; a legend that differs from the levels asked; a missing answer or an unexpected one. Notes (kept,
  not invalid): no legend; the chosen option is not the argmax; the score is not Σ i·p_i (tolerance 1e-3).
  Nothing is repaired: an invalid answer keeps its raw fields in the cache.
- **Extra fields** in answers and usage are kept (laya's `answer_confidence`, `action`; OpenRouter may add some).

## Cache (S2)

- **Key** = sha256 of the canonical JSON of {model, state, questions as an ordered list, provider, params,
  repeat_idx}. The ordered list makes a changed question order or option order miss (`test_dm_cache`); the session
  id (OpenRouter observability metadata, never sent to the provider) is not keyed.
- **Every HTTP 200 is stored**, valid or not, with its cost: a paid answer is never bought twice, and Σ cost per
  chunk reconciles with the spend ledger. Failed calls are not cached (they are logged in `attempts` and re-sent on
  a rerun; the pilot showed they are not billed).
- **A key is written once**; a second, different response for the same key raises `CacheError`.
- **Local models** add their checkpoint settings (revision, subfolder, max_len, head_max_len, device, fp32) to the
  key's params, so a new Laya revision or setting misses.

## Client (S3)

- **Order:** refusals → cache → (offline: `CacheMiss` on any miss) → projection vs. the money left → per call:
  reserve, send, record. Refusals are checked for the whole batch before any cache read or send, also offline
  (the verifier's hand-built test-period and third-party states raise before any transport call).
- **Refusal scope.** (a) third-party and (c) val-B apply to API models only: nothing leaves the machine with a
  local model, and NA-08/NA-09 may predict val-B states locally before the gate (PRD execution-order note).
  (b) test period applies to every model, local included: PREREG §9.4 lets trained models predict test-period Call
  A states before the freeze (that is NA-08's Kaggle path, not this client), but the client has no such use
  before NA-11, so the stricter rule is kept; a later chunk that needs it should add an explicit, logged
  exception. (d) unmasked applies to every model; the registered probes are in `configs/dm.yaml`
  (`unmasked_twin` for PREREG §8.3, `unmasked_robustness` for §11.6). (e) eligibility reads
  `configs/frozen.yaml` `eligible_models` (include = true); `pilot=True` lifts it for the pilot and the smoke test.
  (f) `:free` ids need an entry in `frozen.yaml` `free_model_approvals`; `pilot=True` does not lift it.
  `pilot_period`: with `pilot=True`, a non-synthetic state must be robustness- or train-split with session ≤
  2025-06-30 (from `configs/splits.yaml`, no date literal in `src/`).
- **Provenance is mandatory.** Every call carries a `StateInfo` (source states | synthetic, file, event_id,
  session, split, call, masked, third_party_ok_all, probe); a state-file row must have its event id, session and
  split, a synthetic state has neither session nor split. It is stored in the cache (`meta_json`), which is how the
  verifier lists the sessions sent.
- **Budget.** `dry_run` projects USD for the requests not in the cache; if the projection exceeds min(chunk cap −
  spent − held, total cap − spent − held), `BudgetExceeded` is raised before any send. Each call then reserves its
  own estimate (`SpendLedger.reserve`) and records `usage.cost` against it. An HTTP error releases the hold; a call
  cancelled in flight keeps it (it may have been billed); a 200 without `usage.cost` records price × input tokens
  (`cost_source = computed`; never happened in NA-05). The cache row is written even when the record raises over
  a cap, because the money is spent.
- **Retries.** tenacity, 429 / 5xx / transport errors, at most 5 attempts, full-jitter exponential backoff
  (1 s doubling, cap 30 s) and at least any `Retry-After`; 4xx other than 429 is not retried.
- **`state_as_text`** (`configs/dm.yaml`): a model that refuses state objects gets the state's canonical JSON as a
  string, the same bytes and `state_sha256`. Only `scaledown/classify-1` needs it ("ScaleDown state must be a string
  or an object with only text, document, and document_mime_type"). Respan's span-01 models also refuse objects,
  but with the state as text they refuse every question that is not a `noul` (PREREG §7 forbids noul), so they are
  not listed.
- **The API key** is read from the environment or `.env` and appears only in the Authorization header; it is not in
  the cache, the ledger, the logs or any exception text (`test_cached_rows_hold_the_request_as_sent`).

## Catalog and eligibility (S4)

- The snapshot was fetched once (2026-10-26 17:47 UTC) and kept: the `catalog` stage does not refetch without
  `--force`, so every price and id of this chunk comes from one snapshot. `sha256` hashes the stored entries
  (recomputable); `raw_sha256` the raw list.
- **Every catalog model was tested**, not only the five pilot models: PREREG §8.1's exclusions (errors, silent
  truncation, missing probabilities, rejecting data_collection deny) need at least one call per model. The 18 other
  non-alias, non-`:free` models had a smoke test: 2 canary states (train Call A and Call B, core battery), the 2K
  sentinel test (end / start / none) and the billing check (Q1 alone and the core battery on the two billing
  states): 9 calls each, $0.011 for all.
- **Rounded probabilities are not a §8.1 failure.** Five models return probabilities rounded to 4 decimals and Jev to
  2, so some sums are off 1 by one rounding step (≤ 0.0105). Those answers are invalid under the strict parser and
  the share is reported in the eligibility reason, but the model has probabilities, so it stays eligible. A model is
  excluded for "malformed answers" only when more than 10% of its answers have a structural problem.
- **Silent truncation** = the 2K end sentinel is missed while the start sentinel is found and the no-sentinel control
  is not, with no truncation reported. Both solar models: end 0.18 / 0.32, start 0.85 / 0.91, none 0.002.
  Their tokenizer counts our JSON states at about 1 byte per token (with the state billed per question), so a
  typical state is longer in their tokens than the 2,230-token sentinel state they failed on.
- **Local Laya** (both checkpoints) is listed as eligible (PREREG §8.1).
- `eligible_models` lists all 30 catalog ids and the two local ids with a reason; `free_model_approvals: {}` was added
  (no approval exists; the operator's key, written once and never rewritten by code).

## Local Laya (S5)

- **Revision** `55cf4c4ebb4ebe31b2550e8bdf3bd21b99753851`, laya 0.4.14's reviewed pin for `convaiinnovations/laya`;
  the weights are identical to `main` @ `7b928d82` (LFS sha256 compared on the Hub). The `model.safetensors` sha256
  of each checkpoint is in `configs/dm.yaml` and verified by laya before any weight is read.
- **typed-decisions** (subfolder) and **base** (repository root), both with `max_len` 1024 (PREREG §9.1) and the
  checkpoint's own `head_max_len` (256 / 192). The state goes in as its canonical JSON string (the API's bytes), so
  laya's `state_tokens` equal NA-04's `n_tokens_state` (C01: 685 / 685).
- **fp32** (`agent.amp_enabled = False`): laya autocasts to fp16 on MPS from 5 question rows on, which would make
  an answer depend on the size of the battery. With fp32, Q1 alone, Q1 in the core battery and Q1 in core +
  extended give identical probabilities (interaction 0.0, repeats identical).
- **Exact probabilities.** laya rounds to 4 decimals, so its sums are off 1 by up to ~5e-4. The wrapper replaces
  `_decode_answers` on the instance with one that recomputes each answer's softmax in float64 from the same logits
  and temperature, keeps laya's rounded values as `probabilities_rounded` (and `score_rounded`), and refuses to
  answer if rounding the exact values does not reproduce laya's (a laya change). This is laya 0.4.14's own
  computation, not a fix of its output; sums are exact to 1e-15.
- laya clamps the checkpoint's shipped `choice:11+` temperature (0.10 → 0.5) and warns; Q17 `move_reason` (11
  options) is the only battery question in that bucket.
- MPS, with laya's CPU fallback; the device is the response's `provider` (`local:mps` throughout NA-05).

## Parse (S6)

PREREG §7 and A2.4 exactly: N̂ with m = (−3.5, −2.5, −1.5, −0.75, 0, 0.75, 1.5, 2.5, 3.5) (a test parses the vector
out of PREREG.md), E|N̂|, M, J, W, C, RG with its Under / Over / Fair labels (undefined for |N̂| < 0.5), H without
P(no_material_effect) and renormalized, X, the argmax labels of Q8–Q13 and Q17, U_unc and the expected levels of the
scores, P(mixed). Confidence summaries per question: the model's `confidence`, max p and 1 − H(p)/log k. `derive`
skips invalid answers instead of guessing.

## Canary (S7)

- 30 train-period masked states (20 Call A D0 + 10 Call B D2, tier-stratified by the state's own size words, the
  smallest u = sha256("2026:canary:<event_id>") per tier) and 20 synthetic states built with the codebook in the
  NA-04 layout: 6 Call A with clear news (beat and raise, miss and cut, downgrade, approval, investigation,
  conference) and the 14 numeracy Call B states (one positive news item; the reaction ±{0.3, 0.7, 1.5, 2.5, 4, 6, 9}
  typical daily moves; market move, volume and context fixed).
- The baseline is repeat 0 of the pilot (the canary calls themselves). `compare(model, repeat_idx)` asks the canary
  under another repeat index, which is a new cache key and therefore a fresh call.
- The 20 Call A canary states double as the repeat-variance and question-interaction sample, so the canary's noise
  floor is measured on the canary itself.

## Pilot (S8)

- **Order.** catalog (free) → billing (46 calls) → calibrate (STOP check) → measure → smoke → laya → report. The
  measure stage was projected only after calibration ($0.119 projected, $0.091 actual), so the conservative default
  (per-question billing, 3 bytes per token, × 1.5) never blocked it.
- **Billing basis.** k_n = (tokens(n, long state) − tokens(n, short state)) / (tokens(1, long) − tokens(1, short))
  is the number of state copies billed with n questions; the basis is the median over n > 1. The first rule took the
  maximum and flagged mercury-decide as per-question because one 13-question response reported 161 input tokens for
  a ~2,000-token request (k_13 = 6.2 while k_2 = 0.93, k_4 = 1.01); that response and four more mercury calls billed
  far below their size are repeated identical requests, i.e. a provider prompt cache. The median rule and the robust
  fit below were adopted after that first run; the raw numbers are in `pilot.json`.
- **Cost calibration.** tokens = overhead + state bytes / r_state + question bytes / r_question, fit by least absolute
  deviations then least squares on the inliers (the prompt-cached calls drop out). One rate for both parts missed
  13-question requests by 13–28% for three models (questions tokenize differently from states); two rates bring
  the median error to ≤ 1.6% (90th percentile ≤ 4.5%), 13-question requests ≤ 1.2%. Pilot models: all calls;
  smoke models: their 4 billing and 2 canary calls. Projections use safety 1.1 once calibrated.
- **Truncation states** are Call A-shaped synthetic states whose news is neutral filler (seeded, community-notice
  sentences), sized in ModernBERT tokens (2,048 / 4,096 / 8,192 / 12,288), with the sentinel item first, last or
  absent and one choice question ("Does the text in `news` mention a purple giraffe?"). The start and none variants
  are the controls; a verdict needs both to be right.
- **Latency** uses 160 distinct train Call A states (40 per concurrency level, the same 160 for every model), so no
  provider-side cache can serve a repeat; latency is the successful attempt's wall time.
- **Failure probes.** kev-4b with a 12,288-token state (over its 8,192 context: HTTP 400), the smoke models'
  refusals and the natural 429 / 502s; the key's usage (GET /api/v1/key) before and after shows none was billed.
- **No trials.** The pilot evaluates no model against an outcome (no return of any period is read), so nothing is
  logged in `ledgers/trials.jsonl`.
