## Pipeline and memory

- **One stage per process.** `python -m newsaction.states.build --stage context | mask | states | report`.
  Each stage reads the registered files of the earlier ones.
  - `context` (≈ 35 s, 0.7 GB): company context for every D0/D2 event key, market context per session,
    D2 reaction inputs for train / val-A / val-B.
  - `mask` (≈ 8 min, 2.1 GB; spaCy with 4 worker processes, so it must run as a module): masked title and
    snippet of the 296,082 event articles and the 3,062 A3.5 market articles, and the corpus surname list.
  - `states`: the JSON states and their token counts.
  - `report`: artifacts and the frozen hashes.
- **Context depends only on each key's own history.** `build.compute_context(keys)` gives the same rows for
  a subset of keys as for all of them (fixed session grid from `configs/splits.yaml`, per-symbol rolling
  windows). The determinism test (AC1) uses this to recompute context for a 2,000-row sample.
- **Inputs are registered files only** (CLAUDE.md F21): events, panel_public / panel_test_inputs (t−1
  columns), market_prices, fred_daily, cpi_vintages, earnings_dates, estimates_fy1, companies,
  symbol_tickers, articles_clean (`id`, `third_party_ok` only), market_articles. No sealed file, no lock call.

## Dependencies

- **spaCy English pipeline.** `en_core_web_sm` 3.8.0 is pinned in `pyproject.toml` (`embed` extra) by its
  release-wheel URL, with the hash in `uv.lock` (`uv sync --extra embed`). Only the `tok2vec` and `ner` pipes
  are loaded. This is one download from GitHub (explosion/spacy-models); no article text left the machine.
- **Tokenizer.** The NA-03 ModernBERT-large tokenizer (rev `45bb4654`), from the local cache.

## Codebook (S1; `configs/codebook_v1.yaml`, `states/codebook.py`)

- **Only moves change with the encoding.** E0–E4 apply to every move value (the stock's past-week /
  month / three-month abnormal performance, the six market series, the Call B reaction). Every other scale is
  words in all encodings. The NA-07 study therefore varies exactly one thing.
- **E3 multiples are truncated, not rounded.** All move edges lie on the 0.1 grid, so the shown multiple
  never contradicts its word (|z| = 1.97 is "moderate rise (≈1.9× …)"). E1 rounds ("+2.3σ"; "0.0σ" for
  |z| < 0.05).
- **Multi-day horizons.** Words use z_m{k} = ΣAR / (σ_cc·√k) (NA-01 momentum). The E3 noun is "a typical
  week's / month's / three-month move", which is what σ_cc·√k is, so the word and the multiple agree. Keys
  carry no digits (`past_week`, `past_month`, `past_three_months` for 5 / 20 / 60 sessions).
- **E0** is the raw change: the stock's raw return with the S&P 500 (SPY) return in parentheses, as in the
  PREREG example; percent for prices, basis points for rates, points for the VIX. Raw stock returns over
  5/20/60 sessions exist for public sessions only; E0 states are built only for the val samples.
- **E4** compares |value| with the same series' 252 previous values of the same horizon (≥ 126):
  "a rise larger than 97% of its daily moves in the past year".
- **Additions where §6.10 names a field but §6.11 has no scale** (PREREG §15 row 2): FY1 revision words
  (±1% / ±5% of the earlier consensus, floor $0.10), count words ("none" … "ten", "more than ten"), source
  type words from the domain class, "during today's trading session" (W2 news), the D1 time label "half an
  hour after the open" (no digits), volume vs normal on the attention-multiple scale, "not available".
- **Tier words contain digits** ("one of the 100 largest US companies", "size rank 101–250"). They are the
  exact PREREG §6.11 phrases and identical for every company of a tier, so AC4's digit checks remove these
  three fixed phrases first (REPORT §2, AC4).

## Context (S2; `states/context.py`, `states/macro.py`)

- **Company block.** Sector (GICS level 1); tier words; β_m words; volatility regime (σ_cc vs its previous
  252 values); performance vs the market and its sector over 5 / 20 / 60 sessions; FY1 EPS revision;
  earnings timing.
  - **No industry** (PREREG §15 row 1): ATOM has GICS level 1 only (NA-01 row). An industry level would also
    identify many companies.
  - **FY1** is the first annual period ending after the session. The consensus "now" is the last snapshot
    dated before the session; "before" is the last snapshot dated 31 days before the session or earlier.
  - **Earnings timing.** `earnings_ts` is naive; it is read as America/New_York wall time. A timestamp at or
    after a close belongs to the next session (16:00 means "after the close"), so the windows are
    [close(prev s), 09:15 ET] and [close(prev s), close(s)). The calendar was collected retrospectively
    (NA-00 contract); a report's date is treated as announced in advance.
  - Tickers map to companies through ATOM tickers, price symbols, ATOM `symbol_tickers`, the NA-02 vendor
    aliases and the curated tickers; ambiguous tickers are dropped.
- **Market block** (all through t−1). SPY previous-session move; VIX level percentile and change; 10-year
  yield change; high-yield OAS change; dollar and oil moves; scheduled releases today.
  - Each series is scored against its own 252 previous daily changes: z = change / (1.4826·MAD), with ≥ 126
    observations. In early 2024 the OAS history is too short (FRED's file starts 2023-08), so 18.5% of
    robustness-split sessions show "not available" for it.
  - **Publication lags.** market_prices closes and DGS10 are used as of the previous session (the Treasury
    publishes constant-maturity yields the same evening). The ICE BofA OAS is computed after the US close
    and reaches FRED later, so the state uses the change dated t−2 (`extra_lag: 1`).
  - **CPI release dates** are ALFRED vintage dates that add a new reference month; that leaves out the
    February seasonal re-vintages (2024-02-09). The October 2025 CPI was never published, and the
    data show it (2025-10-24 and 2025-12-18 releases).
  - **FOMC statement dates** come from the Fed calendar (URL in `configs/macro_calendar.yaml`, read
    2026-10-25). The 2025-08-22 notation vote is not a policy statement.
- **Attention block.** Articles vs the 60-session member mean (NA-03 `attention_ratio_*`) and distinct
  stories, of the state's own window (W0 for D0, W2 for D2).
- **Availability.** 45 new columns are registered in `configs/availability.yaml`: context `t_minus_1`
  (earnings flags `w0` / `w2`), macro flags `static`, reaction `d2_reaction`, masked text `w0`.

## Masking (S3; `states/mask.py`, `states/scan.py`, `configs/aliases.yaml`)

**Revision after the first verification (FAIL on AC2).** The first scanner reused the masker's own aliases, exchange
list, stoplist and English date patterns, so it reported 0% while independent scans found company tickers in 3.4% of
val-A D0 states, names in ≥ 1.8%, quarter / half labels in 10.3%, non-English dates in 7.9%, price-move sentences in
2.2% and dollar price targets in 13.4%. Both the masker and the scanner were rebuilt; the operator decided three
policies on 2026-10-25 (price levels, non-English dates, one-word person names; PREREG §15 row 4).

- **Aliases.** ATOM names (all share classes) with suffixes stripped (incl. "& Co.", "& Company", "Hldgs"),
  "(The)" / "(Eli)" moved to the front, leading prefixes of two or more words, and the first word alone when it is
  distinctive; plus curated names and tickers for the companies ranked in the top 150 in any month since 2024-01,
  renamed companies, and about 60 companies whose names were found right before their own "(TICKER)" in the event
  texts but were missing (Super Micro Computer, Wabtec, DuPont de Nemours, PSEG, Old Dominion Freight Line,
  L3Harris, Delta, Booking, Charles River, Southwest, Sands, …).
- **Matching.** Phrases and their distinctive words (4+ letters, not one of the common words or a legal
  suffix) match in any case, with spaces, hyphens and en dashes and both apostrophes interchangeable; a one-word
  name that is a common word ("Target", "Visa", "Delta") or shorter than 4 letters only as written, capitalized or
  in capitals. Products and subsidiaries that are not the company's name are not masked (PRD risks).
- **Tickers.** $T, any upper-case exchange code before a colon (NYSE:, BOATS:, XETRA:), class / venue suffixes
  (T.O, T/PR), possessives (T's) and bare tickers; the bare-ticker stoplist now holds only real English words and
  common upper-case abbreviations (61; ODFL, PAYC, IQV, NDAQ, … were wrongly listed before). A stoplisted ticker is
  still masked with a prefix, in parentheses, as a possessive or before "stock" / "shares". Parenthesized tickers
  and quotes with a percent ("(COST 0.53%)", "MPC-1.32%", "(AAPL +0.87%)") are removed.
- **People** (PREREG §6.3 "person names", including surnames used alone). spaCy PERSON entities that are not a
  company alias, plus every capitalized occurrence of a corpus surname (the last word of a multi-word name seen ≥ 3
  times, not an ordinary word or a company-alias word; `work/states/person_surnames.parquet`) or of a listed public
  figure (`person_names`: heads of state, central bankers, officials, executives named by surname). A one-word NER
  entity counts only as such a surname, after a role noun or before a speech verb; an entity made only of ordinary
  lower-case words ("Balance Sheet", "Buy") is not a name; in a text that looks non-English only names of two or
  more capitalized words count. A name right after a role noun is dropped ("CEO Tim Cook said" → "CEO said");
  otherwise "an executive" with an executive title within six words, else "a person".
- **Dates** → "recently", in English and in French, German, Italian, Spanish, Portuguese, Dutch and Polish (day +
  month, month + year, weekdays, "am 21."), plus numeric dates (ISO, d/m/y, d.m.y, and m/d when the day is 13+ or
  a preposition precedes: "4/15", "on 7/8"; "3/4 of revenue" stays); years (1900–2099) → "the year"; fiscal years →
  "the fiscal year"; quarter labels in any case → "the quarter" / "quarterly" (also "3. Quartal", "T3 2025");
  half-years → "the half-year"; leading datelines and ISINs are removed.
- **Price talk and price levels.** After NA-02's scrub runs again, a sentence with a stock / share price move in
  percent is dropped unless a fundamental noun is its subject ("revenue rose 5%" stays). Price targets: "to $X from
  $Y" becomes "raised / lowered by about N%" (or "slightly"), a lone amount is dropped ("set a price target"); a
  per-share deal or offering price becomes "a per-share price"; EPS, dividends and other per-share fundamentals
  stay.
- **Scanner** (`states/scan.py`; it imports nothing from the masker and does not read the alias file, tested).
  References: ATOM names and their distinctive words, names harvested from the unmasked texts right before the
  company's own "(TICKER)" (≥ 3 times), the ATOM / vendor tickers in every form with its own English-word list, its
  own date patterns in eight languages, period labels in any case, years; plus, for the REPORT, price-move
  sentences, quotes, price levels and a sentinel list of public figures. A one-word name counts as written when it
  is the whole ATOM name ("Target"), and otherwise only if it is not an ordinary lower-case word of the corpus (its
  own vocabulary), so headline words that precede a ticker ("Earnings", "Research") do not count.

## Questions (S4; `configs/questions_v1.yaml`, `states/questions.py`)

- **Verbatim where PREREG is verbatim.** Eight instructions (Q1, Q3, Q4, Q7, Q8, Q14, Q16, Q17) and every
  PREREG option description are used as written; option keys follow PREREG.
- **Written by NA-04** (PREREG §15 row 5), where PREREG gives only options or end points: the instructions of
  Q2, Q5, Q6, Q9–Q13, Q15 (each references `news` / `reaction_so_far`); Q3 / Q4 / Q14 middle levels; option
  descriptions of Q5, Q6, Q7, Q8, Q13, Q16 (two), Q17 (Q8's descriptions plus two).
  - Q1's rise levels mirror the fall ranges ("small rise (0.5–1)"); PREREG lists the ranges for falls only.
- **No noul**; every yes/no item is a two-option choice with neutral keys. The loader refuses `noul` and
  yes/no / true/false keys.
- **Request shape** (OpenRouter Decisions, Laya typed-decisions): `{key: {type, instructions, criteria}}`;
  score criteria are a list, lowest first; choice criteria map key → description. Q17 has 11 options and
  Q8 10; neither API page documents a choice limit (scores ≤ 10 levels for Jev).
- **Hashes** of `questions_v1.yaml` and `codebook_v1.yaml` are in `configs/frozen.yaml`.

## States (S5; `states/build.py`)

- **Shape.** Canonical JSON (sorted keys, compact separators, UTF-8, `ensure_ascii=False`). Top-level keys
  are `attention, company, market, news` for Call A, plus `reaction_so_far` for Call B; market states have
  `market, news`. News items are {headline, snippet, source_type, timing}, in event-list order.
- **Text.** NA-02's scrubbed title / snippet as capped in the NA-03 event list, masked. The summary variant
  is not built: vendor summaries are text of the §11.6 ablation only (CLAUDE.md A6).
- **Call A on D2 (A3.1)** uses the W2 event list and the W2 attention counts. It shares a hash with Call A on
  D0 when the list and every word agree.
- **Call B reaction (D2)** comes from `panel.reactions.build_reactions(period="public")`: G = z_cc,t, the
  stock's and SPY's returns, z_vol,t. The state adds SPY's same-day z against its own history through t−1,
  and volume as a multiple of its 60-session median. Pre-market price talk is not added to Call B (PREREG
  §15 row 3): its numbers would bypass the codebook (CLAUDE.md A4).
- **No test-period Call B.** `build_event_states` refuses Call B events outside train / val-A / val-B, and
  the reaction frame refuses test sessions. NA-11 builds them after the freeze through the lock.
- **Samples.** NA-07: 1,500 val-A + 1,500 val-B D0 events, proportional over tier × month (largest
  remainder), the smallest u = sha256("2026:{event_id}") in each stratum, embargoed sessions excluded; the
  same events in E0–E4. NA-06: an unmasked twin of 1,000 val-A D0 events drawn the same way. Its masked
  twin is the same event in `callA_d0_E3`.

## Tokens (S6) and leaks (S7)

- `n_tokens_state` counts `state_json` without special tokens. `n_tokens_with_questions` adds the call's core
  questions as canonical JSON (the request). AC5's "state + the longest single question" adds the longest
  core question plus 3 special tokens ([CLS] state [SEP] question [SEP]).
- **Tightening (S6).** Before it, Call A met AC5 but Call B did not: p95 state 913 and p95(state + longest
  question) 1,062. `build.fit_news` now drops the lowest-ranked articles (at least one stays) until state +
  longest core question + 3 ≤ 1,024: a cap of 889 state tokens at D0 and 875 at D2 (Call B's longest question
  is 146 tokens). The D2 count reserves the longest possible E3 `reaction_so_far` block, so Call A on D2 and
  Call B keep the same articles and the cut never depends on the reaction. The samples and the unmasked twin
  reuse the D0 E3 cut (`keep`), so an event has the same articles in every encoding and in both twins.
  No text had to be cut; whole articles were enough (PREREG §15 row 5 (d)).
- **Events without text.** An event whose every article loses its text after masking (price talk that NA-02's
  scrubber missed and the second scrub removed: "Shares of eBay declined on Thursday…") gets no state; the
  counts per file are in `artifacts/NA-04/build_states.json` (PREREG §15 row 5 (e)).
- **Laya.** The model card gives 1,024 tokens with `head_max_len = 256`, i.e. about 768 for the state. AC5's
  900 target is the PRD's; `token_stats.csv` also reports the share of states within 768 for NA-08.
