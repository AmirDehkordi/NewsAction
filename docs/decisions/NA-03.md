## Pipeline and memory

- **One stage per process.** `python -m newsaction.events.build --stage labels | counts | fit | scores |
  compare | events | project`. Each stage reads the registered files of the earlier ones.
- **Peak RSS** (24 GB machine): labels 0.3 GB, counts 0.8, fit 9.2, scores 6.6, compare 0.4, events 6.3,
  project 1.1.
  - Fit holds the fit-window embeddings (359K × 384, float32) and the float64 copy that the logistic
    regression uses.
  - Embeddings are streamed in 131K-row batches (`learned.map_embeddings`). Only the needed rows are
    gathered, and articles are read with a pyarrow `keep` filter.
  - This cut a first draft's 6 GB article read to 1.7 GB.
- **Determinism.** A full rerun of the seven stages reproduced every sha256 in `work/events/`, the three
  CSVs and `configs/frozen.yaml`, and appended no trial (`ledgers/trials.jsonl` stayed at 92 lines before
  the sensitivity run).
  - LightGBM runs with `deterministic`, `force_row_wise` and a fixed thread count.
  - Models are stored as JSON / LightGBM text, not pickles.
  - Model metadata carries no timestamps: the manifest records when and from which commit.
- **Trials are logged idempotently** (`events/trials.py`). A record identical to one in the ledger is not
  appended again, so deterministic reruns do not inflate the deflated-Sharpe trial count. A changed value
  is a new evaluation and is logged.

## Labels (S1)

- **Source.** Labels come from `panel_public`: the representative-class member rows, restricted to covered
  member-months.
  - The six-day CAR is the panel's purged, delisting-aware `car6_z`, i.e. NA-01's frozen target code.
  - The delayed five-day CAR is derived from it: Σ_{j=1..5} AR = car6_z·σ√6 − AR_t. The two labels
    therefore share one purge and one delisting rule.
  - A test re-sums AR_cc over t+1…t+5 from the panel for 60 val-A labels and matches to 1e-9.
- **Missing labels.** A label with a missing input is NA, never "not material". `material` and `delayed`
  are nullable booleans.
- **No targets module.** `events/labels.py` never imports `panel.targets`, and the label file holds no
  test-period row.
- **Underreaction kept.** With √5 vs √6 scaling, some delayed days are not material: a 2.1σ five-day drift
  is only 1.94σ over six days. The delayed-recall constraint is therefore a separate guard, not a subset of
  material recall.

## Filters (S2–S3)

- **Rule filters** use NA-02's vendor fields exactly as §6.6 states them.
  - F1: `sentiment_direction` ≠ "Neutral" (a missing sentiment does not count).
  - F2: intensity ∈ {Immediate, Short-Term}.
  - F3: `source_class` ∈ {press_wire_primary, major_outlet}. This is NA-02's class with the vendor
    primary-source override, i.e. the vendor-based selection field, not `source_class_domain`.
- **F4** is the max novelty of the ticker-day's kept articles.
- **F5 / F6 tuning.**
  - Tune recall at the 30% budget: F5 picks C = 0.1 (0.3946; the grid spans 0.3933–0.3946), F6 picks
    15 leaves, 400 minimum child samples and 200 rounds (0.4212; grid 0.4142–0.4212).
  - All 12 grid points are in `ledgers/trials.jsonl` (kind `filter_hparam`, split `train`).
- **F6 attention ratio.** It counts usable articles, near-duplicates included, against their mean over the
  company's member sessions among the previous 60.
  - The corpus holds a company's articles only while it is a member, so a joiner's first weeks would
    otherwise look extremely busy.
  - The ratio is floored at 1/60 when the mean is 0, which caps it at 60 × the count; trees are unaffected.
- **No `Categorical` codes.** F6 category codes come from a fixed vocabulary map. pandas 3 deprecates
  building a `Categorical` from values outside its categories, and an unseen tag would have hit that path.

## Comparison and rule (S4)

- **`select.compare` evaluates on val-A only.**
  - `assert_val_a` runs on the labels and again on the joined sample.
  - `run_compare` filters the ticker-days to val-A before the join.
  - Val-B rows of `labels_public` are never read into a statistic.
- **`apply_rule` is a pure function of the comparison table.**
  - The test recomputes it from the committed CSV and compares it with `frozen.yaml`.
  - `rule_trace` reports the choice without the delayed-recall constraint and whether the constraint binds.
- **Frozen filter.** `filter:` holds the PRD keys {id, threshold, budget_share, rule_version,
  comparison_sha} plus:
  - `tie_u_max` and `tie_seed`, so a rule filter's thinning can be reproduced;
  - `selected_share_val_a`;
  - `constraint_binding`;
  - `comparison_file`.
- **Frontier** (`frontier.csv`, Figure 6 data): budget shares 5 %…50 % for all seven filters. F0's line is
  the "random day with news" baseline. All 70 points are logged (kind `filter_frontier`).

## Events (S5)

- **Window and articles.**
  - Events cover the robustness start to the test end (2024-01-02 … 2026-07-31). 2023-H2 is warmup and
    has no events.
  - The article list is ordered by the frozen filter's article score, then t_avail, then id.
  - `rank` 1 is the best third-party-OK article. The ticker-day `filter_score_*` can be higher when the
    best article is not third-party OK (only in 2024).
- **Token block.**
  - Each article renders as its title and snippet joined by a line break, with empty parts left out:
    41K kept titles and 37K snippets are empty after NA-02 scrubbing.
  - Articles are separated by a blank line.
  - Tokens are counted with ModernBERT-large @ `45bb4654` without special tokens. That revision
    (2025-01-15) only changes `model_max_length`; the weights are the Dec-2024 checkpoint.
  - The cap never had to truncate a snippet. Dropping the lowest-scoring articles was always enough:
    max tokens 598 (D0) / 599 (D2), and 0 truncated snippets.
- **Writer.** Event files are written with pyarrow (explicit list<struct> type for `news_w0` / `news_w2`,
  t_avail as timestamp[us, UTC]) and registered with `io.register_file`, like NA-02's embeddings.
  `pd.read_parquet` cannot rebuild a nested ArrowDtype containing a timestamp from pandas metadata. Those
  columns read back as arrays of dicts.
- **Context columns.**
  - Tier and representative class come from `panel/tiers_monthly.parquet` (t−1). Event building reads no
    panel file with returns.
  - Window columns carry a `_w0` / `_w2` suffix so that the availability registry can type them; 56 new
    registry entries.
  - The PRD's event key `event_id` shares its name with the vendor story-cluster column, which is
    registered `selection_only`. It is an identifier, not a model input. NA-04 should not pass it to
    `check_inputs`.
- **Non-English articles** (`non_english_hint`) are kept and counted (`n_non_english_*`, about 5% of
  listed articles). NA-04 decides whether to drop them before masking (NA-02 owner decision 4).

## Projection (S6)

- **Components.** `call_projection.csv` has three sections.
  - Events per split × tier × window.
  - NA-11 components per split: A_D0, B_D2, B_D1, A_D2 (A3.1), final_selection, ablations, llm_baseline,
    market.
  - Four plan totals with the cap flags.
- **A_D2 cache hits.** A D2 event whose article list is identical to its D0 event's has an identical
  Call A state, which hits the cache, so it is not counted (2,600 val-A, 2,251 val-B, 6,399 test).
- **Assumptions.**
  - Ablations: 12,000 events × 3 calls.
  - Final selection: 2 API survivors × every val-B D0 event (core battery).
  - The primary API instrument gets +600 question tokens on every call (extended / explain), which is
    conservative for Call B's two explain questions.
